DSA top-k indexer（DeepSeek-V3.2 稀疏注意力索引器，flashinfer-trace 定义 `dsa_topk_indexer_fp8_h64_d128_topk2048_ps64`）—— 大 batch 混合长度。
- 工作负载 8635db8f：B=27，seq_lens=[133,136,136,141,1766,198,159,134,202,152,136,275,5806,142,177,492,190,302,178,226,134,137,165,244,130,200,129]（共 12220 token，最长 5806），block_table (27,91)。
- 算子语义：对每个 batch b，只看 seq_lens[b] 个有效 token（token t 位于 page = block_table[b, t // 64]、页内偏移 t % 64）；每个 head h 的分数 = relu(q[b,h]·k_t)，按 weights[b,h] 加权后对 64 个 head 求和得到每个 token 的标量分数；取分数最大的 min(2048, seq_lens[b]) 个 token，输出其**全局 token id**（= page_id × 64 + 页内偏移），其余位置填 -1。
- 布局：q_index_fp8 (B,64,128) float8_e4m3fn；k_index_cache_fp8 (num_pages=11923, 64, 1, 132) int8 —— 每页先放 64×128 B 的 fp8_e4m3 数据（每 token 一行 128 B），紧接 64 个 fp32 per-token scale（每个 4 B），真实 k = fp8 × scale，scale = 该 token 128 维的 absmax / 448；weights (B,64) float32；seq_lens (B) int32；block_table (B, max_num_pages) int32 → topk_indices (B,2048) int32。
- 数据：seq_lens 与 block_table 用 ./ref/data/ 下的 safetensors 真实数据（flashinfer-trace 工作负载）；q_index_fp8、weights 随机生成，k cache 由随机 bf16 按上述格式量化打包。
- 参照：./ref/ref_entry.py 的 `run(q_index_fp8, k_index_cache_fp8, weights, seq_lens, block_table) -> topk_indices`（AKO agent kernel fast_split_v6，load_inline 首次调用时 JIT 编译；device time **5.0 µs**（jobs 1074317/1074336 实测 4.99/4.99 µs，profiler kernel-only span，1 个 kernel；同 job CUDA events 中位数 10 µs，刷 L2、warmup 10 / iters 50））。
