2026-10-23：上游 `731d977` 补齐的 `goal_single_shape/dsa_topk_indexer/topk_T3_C_large/fable-5.1` 已完成 B200 精度、重复调用与性能复测，候选源码未修改。任务 `tasks/1341194`。当前仓库 135 个实现目录均已有各自输入范围与判据下的通过证据；原有全 shape 覆盖限制仍见[总览](../remainder-03413a0-20261022/README.md)。

## 输入及精度

使用官方 workload `8635db8f` 的 seq_lens 和 block_table：B=27，max_pages=91，最长序列 5806，总有效 token 12220，物理缓存 11923 页，H=64、D=128、K=2048、page_size=64。

按 GOAL.md 的有效缓存布局生成随机 BF16 key，每 token 取 absmax/448 作为正 FP32 scale，量化到 FP8 e4m3fn。每页先放全部 FP8 数据，再放 64 个 scale；没有把通用 int8 随机字节解释为浮点 scale。Q 随机生成后转 FP8。测试有符号正态权重以及其绝对值形成的非负权重，两种分布均使用种子 0、42。

以官方 FP32 数学 reference 为中心，精确比较排序后的全局 token 成员集合及 -1 padding。每种分布、每个种子连续调用 100 次，逐次检查全部输出，并检查缓存 scratch 已全部清零，合计 400 次均通过。性能测量前后亦重新检查输出，没有放宽判据或以容差替代成员集合。

## 性能

同一张 B200、同一任务，三轮各 50 次热缓存及 50 次冷 L2 测量。以下是每轮 kernel-span 中位数的范围，单位 µs；不等同于 Python 调用端到端时间。每种分布在种子 0 上计时。

- 非负权重：热缓存 **8.5760–8.6240**；冷 L2 **9.3280–9.4080**。
- 有符号权重：热缓存 **12.6395–12.6560**；冷 L2 **13.2475–13.2635**。

两种分布用于检查数据依赖路径的性能变化，不等于复现历史 benchmark 的全部输入。历史约 9 µs 的结果来自另一任务和环境，本轮没有重建其 reference kernel 的同条件 A/B，因此不据此声称相对历史结果的加速比。

前后负载频率检查均通过：至少 90% 样本 SM 时钟≥1900 MHz。存在 sw_power_cap 功率限制标志，具体时钟分布保存在日志；不能描述为全程固定 1965 MHz 或完全没有限频。频率抽样不是整个计时区间的连续保证。
